Especificación Formal

Las 5 Categorías de Antipatrones (Taxonomía A–E)

Tanto el dataset sintético como el arnés de benchmark CAS se basan en cinco modos de fallo arquitectónicos de la IA comercial:

CATEGORÍA A Frontera de Dominio

Filtración de ORM y Bases de Datos

Acoplar decoradores de TypeORM (@Entity, @Column) o el cliente de Prisma en entidades de dominio. Destruye la portabilidad e impide testing unitario sin base de datos activa.

✓ Resolución: Entidades POJO/TS puras sin imports externos; persistencia delegada a adaptadores de repositorios.
CATEGORÍA B Adaptador de Interfaz

Fuga de Presentación y HTTP

Pasar objetos de Express (req, res) a los casos de uso. Provoca que las reglas de negocio dependan de cabeceras y códigos de estado HTTP.

✓ Resolución: DTOs fuertemente tipados y retornos basados en la mónada funcional Result entregados a controladores.
CATEGORÍA C Invariantes

Obsesión Primitiva

Usar strings crudos para identificadores de dominio, correos o números de impuestos sin chequeo de invariantes. Permite que estados inválidos circulen por la aplicación.

✓ Resolución: Value Objects con constructor privado, validación defensiva por regex y métodos fábrica estáticos.
CATEGORÍA D Rigor de Tipado

Proliferación Explícita de any

Recurrir a any como atajo ante tipos complejos, anulando todas las garantías de seguridad del compilador de TypeScript.

✓ Resolución: Genéricos estrictos, unknown con guardas de estrechamiento (type guards) y política de cero any.
CATEGORÍA E Responsabilidad Única

Antipatrón God Class (Clases Monolíticas)

Servicios monolíticos que realizan validación, persistencia en base de datos, envío de correos y llamadas a pasarelas de pago en un solo método de 400 líneas.

✓ Resolución: Casos de Uso orquestados con responsabilidad única que inyectan interfaces de Puertos abstractas.

Ingeniería de IA Industrial

La Factoría de Modelos: Ingesta Continua de SLMs

El proyecto desacopla el entrenamiento de un modelo específico. Conforme surjan nuevos SLMs de pesos abiertos (Qwen 2.5, Llama 3.2, Gemma 2, DeepSeek), la factoría automatiza su especialización:

ETAPA 1: REGISTRO DE RECETAS

Modelos Declarativos

Recetas YAML (recipes/*.yaml) que definen proyecciones objetivo, delimitadores y precisión numérica.

ETAPA 2: RÁFAGA LORA

Pérdida Enmascarada

Calcula gradientes exclusivamente sobre las refactorizaciones del asistente mediante response_template, con límites temporales automáticos.

ETAPA 3: GGUF EN EL BORDE

Cuantización Atómica

Fusiona deltas LoRA en pesos FP16 y exporta binarios GGUF Q4_K_M para inferencia local con latencia inferior a 15ms.

// 1. CAPA DE DOMINIO: Entidad Pura de Negocio (src/domain/entities/Order.ts)
export class Order {
  private constructor(
    public readonly id: string,
    public readonly customerId: string,
    public readonly total: number,
    public readonly status: 'PENDING' | 'PAID'
  ) {}

  public static create(customerId: string, items: OrderItem[]): Order {
    if (!items || items.length === 0) {
      throw new DomainError('La orden debe contener al menos un ítem');
    }
    const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
    return new Order(crypto.randomUUID(), customerId, total, 'PENDING');
  }
}

// 2. CAPA DE APLICACIÓN: Contrato de Puerto (src/application/ports/IOrderRepository.ts)
export interface IOrderRepository {
  save(order: Order): Promise<void>;
}

// 3. CAPA DE APLICACIÓN: Caso de Uso (src/application/use-cases/CreateOrderUseCase.ts)
export class CreateOrderUseCase {
  constructor(private readonly orderRepo: IOrderRepository) {}

  async execute(dto: CreateOrderDTO): Promise<Result<Order, DomainError>> {
    try {
      const order = Order.create(dto.customerId, dto.items);
      await this.orderRepo.save(order);
      return Result.ok(order);
    } catch (err) {
      return Result.fail(err as DomainError);
    }
  }
}

// Código Legado Acoplado (Express directo + SQL en el Handler)
import express from 'express';
import { db } from './database';

app.post('/api/orders', async (req: any, res: any) => {
  const { customerId, items } = req.body;
  
  // Validación en línea mezclada con presentación HTTP
  if (!items || items.length === 0) {
    return res.status(400).json({ error: 'Ítems requeridos' });
  }

  const total = items.reduce((sum: any, i: any) => sum + i.price * i.qty, 0);

  // Filtración de base de datos directa en controlador web
  const result = await db.query(
    'INSERT INTO orders (customer_id, total, status) VALUES ($1, $2, $3) RETURNING id',
    [customerId, total, 'PENDING']
  );

  res.status(201).json({ orderId: result.rows[0].id, total });
});
