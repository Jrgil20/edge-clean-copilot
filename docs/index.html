Formal Specification

The 5 Core Antipattern Categories (Taxonomy A–E)

The synthetic training dataset and the CAS benchmark are grounded in five systematic failure modes of standard commercial AI models:

CATEGORY A Domain Boundary

ORM & Database Leaks in Domain

Directly coupling TypeORM (@Entity, @Column) or Prisma client into pure business entities. Destroys portability and makes unit testing impossible without an active database.

✓ Resolution: Pure POJO/TS entity with zero imports; persistence handled by repository adapters.
CATEGORY B Interface Adapter

HTTP & Presentation Leakage

Passing Express req and res into application use cases. Causes business logic to depend on HTTP status codes and headers.

✓ Resolution: Strongly-typed Request DTOs and functional Result types returned to controllers.
CATEGORY C Invariants

Primitive Obsession

Using raw strings for domain identifiers, emails, and tax IDs without invariant checks. Allows invalid instances to circulate through the system.

✓ Resolution: Value Objects with private constructors, regex invariants, and static factory create methods.
CATEGORY D Type Rigor

Explicit any Proliferation

Using any as an escape hatch on complex types, disabling TypeScript's compiler type-safety guarantees.

✓ Resolution: Strict generics, unknown with type narrowing guards, and zero-any policy.
CATEGORY E Single Responsibility

God Class Anti-Pattern

Monolithic services that perform validation, database persistence, email dispatch, and payment gateway calls in a single 400-line method.

✓ Resolution: Orchestrated single-purpose Use Cases injecting abstract Port interfaces.

Industrialized AI Engineering

The Model Factory: Continuous Open-Weight Ingestion

The project decouples training logic from specific foundational models. As new models emerge (Qwen 2.5, Llama 3.2, Gemma 2, DeepSeek), the factory pipeline automates adaptation:

STAGE 1: RECIPE REGISTRY

Declarative Models

YAML recipes (recipes/*.yaml) define target projections, response delimiters, and hardware dtypes.

STAGE 2: LORA BURST

Loss-Masked Training

Computes loss exclusively on assistant refactorings using response_template, capped by wall-clock timers.

STAGE 3: EDGE GGUF

Atomic Quantization

Merges LoRA deltas into base FP16 weights and converts to Q4_K_M GGUF binaries for fully local inference.

// 1. DOMAIN LAYER: Pure Business Entity (src/domain/entities/Order.ts)
export class Order {
  private constructor(
    public readonly id: string,
    public readonly customerId: string,
    public readonly total: number,
    public readonly status: 'PENDING' | 'PAID'
  ) {}

  public static create(customerId: string, items: OrderItem[]): Order {
    if (!items || items.length === 0) {
      throw new DomainError('Order must contain at least one item');
    }
    const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
    return new Order(crypto.randomUUID(), customerId, total, 'PENDING');
  }
}

// 2. APPLICATION LAYER: Port Contract (src/application/ports/IOrderRepository.ts)
export interface IOrderRepository {
  save(order: Order): Promise<void>;
}

// 3. APPLICATION LAYER: Use Case (src/application/use-cases/CreateOrderUseCase.ts)
export class CreateOrderUseCase {
  constructor(private readonly orderRepo: IOrderRepository) {}

  async execute(dto: CreateOrderDTO): Promise<Result<Order, DomainError>> {
    try {
      const order = Order.create(dto.customerId, dto.items);
      await this.orderRepo.save(order);
      return Result.ok(order);
    } catch (err) {
      return Result.fail(err as DomainError);
    }
  }
}

// Coupled Legacy Code (Direct Express + SQL in Handler)
import express from 'express';
import { db } from './database';

app.post('/api/orders', async (req: any, res: any) => {
  const { customerId, items } = req.body;
  
  // Inline validation mixed with HTTP presentation logic
  if (!items || items.length === 0) {
    return res.status(400).json({ error: 'Items required' });
  }

  const total = items.reduce((sum: any, i: any) => sum + i.price * i.qty, 0);

  // Direct database leak in web controller
  const result = await db.query(
    'INSERT INTO orders (customer_id, total, status) VALUES ($1, $2, $3) RETURNING id',
    [customerId, total, 'PENDING']
  );

  res.status(201).json({ orderId: result.rows[0].id, total });
});
